## 3. 统一输出规格

- 请求单张正方形 1024 × 1024 PNG、真正透明背景；最终格式与尺寸必须实测，不能只相信提示词。
- 母版完成后，固定镜头、人物比例、脸部位置和脚部基线。
- 所有帧完整包含头顶火焰、尾焰、耳朵、手脚，四周留至少约 8% 透明余量。
- 后处理统一为 256 × 256 运行时 PNG，可保留 1024 主帧供后续修图。
- 推荐运行时画布锚点 `(128, 232)`，表示身体两脚之间的地面参考点；横向对齐身体，不按尾巴最外沿居中。
- 同一套素材使用统一缩放比例。允许为锚点对齐做小幅平移，不可每帧分别按外接矩形撑满画布，否则角色会忽大忽小。
- 第一轮建议在现有 88px 方形宠物点击区域内预览，也检查 64、96、128px。角色实际可见尺寸受透明边距影响，不能只看画布宽度。
- 不让图像生成模型绘制棋盘格、帧编号、网格或说明文字。

## 5. 后处理和实际验收

1. 生成文件先复制到工作区的 `masters/`，保留原输出，不覆盖参考图。
2. 检查 PNG 是否含真实 alpha、角落是否透明、尾巴内圈是否镂空；不能只看棋盘格预览。
3. 逐帧检查脸、耳朵、手脚、尾巴、火焰连接与色彩是否漂移。模型不保证像素级一致，不通过就定点修正。
4. 为所有帧确定同一缩放比例和身体锚点；保留行走的自然轻微起伏，消除构图漂移。
5. 输出统一 256 × 256 RGBA 到 `frames/`；右向可以运行时镜像。
6. 待机三帧和眨眼帧尽量锁定身体像素。若模型改了身体，从合格输出仅提取需要变化的区域合成。
7. 把处理后的帧拼成图集时，由程序按固定单元格拼接，不要求模型直接画整张图集。
8. 输出带实际帧矩形、时长、方向、锚点的 `manifest.json`；在 PNG 存在前不创建假装可用的运行时清单。
9. 生成透明 APNG 或 WebP 动画、浅色和深色背景对照图，以及 88px 预览。GIF 透明色能力有限，不作为生产源文件。
10. 检查浏览器中所有图片加载成功、动画有像素变化、帧边缘不裁切。减弱动效模式应显示静态母版。

## 6. 动画时序与业务契约

下列数值是第一轮调试起点，不是 Codex 内部实现或已经实测的参数。当前并未读取 Codex 桌宠源码。

| 场景 | 播放方式 |
| --- | --- |
| 待机火焰 | `idle-01 → idle-02 → idle-03 → idle-02`，每帧约 160ms，循环 |
| 眨眼 | 每 4.5-6.5 秒随机触发一次；半闭 45ms、全闭 90ms、半闭 45ms，再回到睁眼 |
| 左向拖拽 | `walk-left-01` 到 `06`，每帧约 90-110ms，连续移动时循环 |
| 右向拖拽 | 同一组行走帧水平镜像 |
| 按住但停止移动 | 约 150ms 无有效位移后回到当前朝向的待机，不持续原地踏步 |
| 仅垂直移动 | 保留上次朝向，可以继续轻步态；不要左右抖动 |
| 释放 | `settle-01` 约 90ms、`settle-02` 约 110ms，然后待机 |
| 取消拖拽 | 清理捕获和临时状态，回待机；不得触发点击气泡 |
| 减弱动效 | 只显示静态母版；位置拖拽正常工作 |
| 页面后台/宠物隐藏 | 停止帧时钟与眨眼计时，恢复显示时重置下一次眨眼 |

运行时注意：

- 使用 `idle / pressed / dragging / settling / hidden` 模式，朝向独立为 `left / right`。
- Pointer Events 记录主指针、按下位置、抓取偏移和最大移动距离，超过约 6px 才判定拖拽。
- 点击判定使用原始指针移动距离，不用被边界截断后的角色位移，避免边缘拖动误判点击。
- 方向依据一小段累计水平位移或速度切换，不能每个 pointermove 都要求超过 4px，否则慢拖无法转向。
- 松开、pointercancel、lostpointercapture、窗口失焦都要清理拖动；只有正常松开且未拖动才允许打开气泡。
- 使用 requestAnimationFrame 合并位置更新；不要每一帧创建 React 全局状态更新。动画可用 CSS steps 或局部渲染时钟。
- 同时只播放一种身体姿势。眨眼只在待机触发，拖动打断眨眼，回弹打断待机。
- 所有图片预加载、解码成功后切换新素材；加载失败应保留可用静态图，不能显示空白角色。
- 视口过小时安全区域上下限需一致计算，复用已有 visualViewport 能力，保证整个固定尺寸点击区域可见。
- 这些是网页窗口内的交互规则，不包含操作系统桌面窗口、托盘或窗口穿透。
