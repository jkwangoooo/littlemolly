# 幸福小Molly

个人日程 PWA，使用 React 19、TypeScript、Vite、IndexedDB 和 Supabase。支持执行今天、准备明天、按日期查看计划、三餐、补剂、健身、自定义事项、休息日家务、复制昨天、选项管理及业务备份。编辑使用底部面板，选项页从日程页右上角进入。

**账密改造源码与本机自动验收已完成（2026-10-13），本次尚未执行生产迁移、W 账号准备、远端环境更新或发布。** 现行方案见 [账密改造详细执行文档](docs/43-账密改造详细执行文档.md)，实测与部署交接见 [本地实施记录](docs/44-账密改造本地实施与部署交接.md) 和 [HANDOFF.md](HANDOFF.md)。历史 S1-S6 报告中的本地注册、双身份绑定和换设备重新注册流程已被本次方案取代。

## 启动

1. 安装依赖：`npm install`。
2. 开发环境配置 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_ANON_KEY`。
3. 启动：`npm run dev`，以 Vite 输出的浏览器地址为准，通常为 `http://127.0.0.1:8800`。
4. 登录可信管理入口已准备的账号 `W`。首次登录需要网络和有效的 Supabase Auth 配置；没有配置时会显示原因，不能本地注册绕过。

本机验收脚本使用隔离的假 Auth 与假云端，无需生产密码或管理员密钥。已有部署凭据继续使用受保护的本机配置，不重复向用户索取，不打印具体值。

### 本地 PostgreSQL 仿真数据库

```bash
npm run db:local:init    # 首次创建并执行当前迁移
npm run db:local:status
npm run db:local:start
npm run db:local:stop
npm run db:local:reset   # 备份旧数据后按当前迁移重建
```

默认地址为 `127.0.0.1:55432`，数据库名和用户名都是 `molly`。可用 `npm run db:local:psql -- -c "select now();"` 查询。详细说明见 [本地数据库说明](docs/本地数据库说明.md)。它只用于仿真，不改变浏览器 IndexedDB 作为业务唯一写入落点的设计。

### 快捷启动器

双击项目根目录的 `launch.cmd`，或在终端运行 `node scripts/launcher.mjs`，按菜单执行已有脚本。

```bash
launch.cmd
launch.cmd 8                      # 直接执行 verify:local
node scripts/launcher.mjs --list  # 查看任务清单
```

依赖未安装时先执行第 13 项；第 11 项 SQL 验收需要本机 PostgreSQL，未纳入第 12 项 `all`。

## 账号、会话与数据归属

- 页面只使用「账号」和「密码」，仅接受 `W` / `w`；内部 Auth 标识固定为 `w@molly.local`。密码原样传给 Auth，不做 trim，不存入源码、前端环境变量或本地资料。
- Supabase Auth 是唯一认证来源。账号资料、业务根表、同步状态和待上传队列使用同一个 Auth UID；子表按父链检查归属。服务端使用受保护的 UID allowlist，客户端账号校验不能代替 RLS。
- 首次登录、退出后重新登录需要网络。启动会验证持久会话；新设备或未初始化的工作区先恢复该 UID 的云端数据，准备完成后才开放业务页。恢复失败不能当成云端为空，也不能先播种再覆盖云端。
- 已完成准备的工作区可在暂时断网时使用离线缓存，编辑仍存本地。离线缓存不验证密码，不代表新的登录成功，也不允许上传；联网重新核验身份后再补传。
- 普通退出关闭本机工作区，保留业务数据和未上传队列。同账号再次认证后打开原工作区；旧 localStorage JSON 不能重新创建已验证会话。

`DB_VERSION = 8`，共 18 张仓库：10 张业务数据、`users` 资料缓存、7 张设备/隔离/迁移状态仓库。v8 将旧账号和旧同步状态隔离，移除活动密码认证信息。旧业务数据保留以供盘点，不能通过“账号只剩 W”猜测归属或自动合并。明确旧 owner 与目标 UID 后才能执行受保护的迁移；目标已有数据或关联冲突时拒绝静默覆盖。

新业务备份为 **v3**，不含密码或 token，继续只读兼容 v1/v2。导入经过全量字段、父子关联和 ID 冲突校验，以当前已验证 UID 为归属，不从备份创建账号或会话。被清除且从未上传的编辑无法凭账号恢复，重要内容仍应保留独立备份。

## 服务层与上传

IndexedDB 仍是业务唯一写入落点，`DATA_BACKEND` 恒为 `'local'`。认证需要 Auth；日程读写仍通过本地业务服务完成。上传是增量上行通道，手动整体替换继续要求确认损失范围和「不可撤销」。新设备的首次恢复只针对尚未初始化的工作区，不构成通用自动双向合并。

```text
src/services/
  capabilities.ts  唯一的 Supabase 构建期环境变量读取点
  contracts.ts     页面接口与状态契约
  api/             界面唯一入口，认证/同步编排动态加载
  local/           资料缓存、IndexedDB、业务服务、备份及工作区迁移
  sync/            Auth 生命周期、工作区准备、上传与整体替换
  cloud/           errors / identity / rpc / supabase 四个传输模块
  session.ts       已准备的运行时身份与代次，不负责密码认证
```

本地写入口在事务内记录待上传项。推送固定 owner 与身份代次，读取主表最新行，先发 delete 再发 upsert，按依赖排序后切批次。身份变化后旧异步结果不得清新队列或写新工作区。全局调度器在 `main.tsx` 接线；状态卡片读取本地状态，明确的认证、首次恢复和上传才请求云端。

本地保存、认证成功、上传完成和恢复完成分别表述。队列为空只说明本机队列已排空，不能宣称「已同步」。

只有一个 Vite 构建。`npm run build` 生成 `dist/`；`npm run build:no-empty` 覆盖写构建产物，供 PWA 验收使用。Supabase SDK 保持动态加载。无 Auth 配置的构建可渲染配置错误页面，不能作为功能完整的本地登录版本发布。

## 本地验收命令

下列数量为本次已确认的实测基线，均已通过。类型检查、lint 和 `build:no-empty` 的最终退出码均为 0。本机隔离 Auth/云端与临时 PostgreSQL 的结果不能代替真实 W、生产迁移、线上恢复或真机验收。

```bash
npm run typecheck           # 类型检查（已通过）
npm run lint                # 静态检查（已通过）
npm run build               # 生产构建
npm run build:no-empty      # 覆盖写构建产物（最终构建已通过）
npm run check:dates         # 日期引擎规则回归（48 项）
npm run check:local-data    # 本地结构、v8 隔离与写入契约（75 项）
npm run check:backup        # v3 无凭据备份及 v1/v2 兼容（96 项）
npm run check:cloud-parity  # 页面门面、Auth 边界与 SQL 权限（114 项）
npm run check:sync          # 队列、统一 UID、映射与替换规则（149 项）
npm run check:feedback      # 身份变化时的反馈状态回归（16 项）
node scripts/验证认证并发.mjs # SDK 事件与认证准备竞态（12 项）
node scripts/验证旧工作区迁移.mjs # 真实 v6/v7 旧库升级、隔离与显式复制（69 项）
node scripts/验证部署凭据护栏.mjs # 部署凭据与错误输出护栏（20 项）
npm run verify:local        # 真实浏览器业务与认证闭环（172 项）
npm run verify:pwa          # 生产应用壳、离线缓存、键盘避让与缓存头（64 项）
npm run verify:sync         # 假 Auth/云端闭环与异步身份隔离（195 项）
npm run verify:sql          # 临时 PostgreSQL 真跑 7 个迁移与四个 RPC（87 项）
npm run icons               # 由 public/favicon.svg 生成四张 PNG 图标
```

静态回归五件套与 `check:feedback` 无需浏览器。日期检查直接导入 TypeScript 源码，需要支持类型剥离的 Node；本机优先使用已配置的 Node 22.18+。数据库迁移只追加，界面只引用门面，业务写入及队列使用同一事务。

`node scripts/验证认证并发.mjs` 用受控 SDK 事件验证准备期间退出、迟到退出广播、UID 变化、最终会话重读及退出后连续重登。`node scripts/验证旧工作区迁移.mjs` 的 69 项覆盖真实 v6 旧库 19 项和 v7 旧库 50 项，验证升级到 v8、旧身份隔离、事务中断回滚、幂等重试及业务完整复制。`node scripts/验证部署凭据护栏.mjs` 验证部署前凭据和错误输出不会泄漏敏感信息。三项与 `check:feedback` 均独立于启动器 `all`，交付前须另跑，不能代替真实 Auth 或生产验收。

`verify:local` 自建临时 Vite 服务与 Chrome/Edge 无头实例，覆盖 v1-v8 升级、W 登录、错误密码、无公开注册入口、准备失败不开放业务、退出重登、伪造旧会话拒绝、旧身份隔离、备份、日期与日程交互、并发建计划以及桌面/手机布局。Auth 与恢复使用隔离夹具，不能证明生产账号或真实 GoTrue 已配置。

`verify:pwa` 托管生产产物，覆盖 service worker 生命周期、只缓存同源应用壳、本轮构建的认证与离线懒加载资源预缓存、首次在线登录后直接离线刷新、首次离线打开账号页读取本地状态、联网校验、新版本等待用户刷新和更新安装失败保留旧首页。另覆盖无 Auth 配置的独立资源清单、安装与存储状态、软键盘避让和静态部署配置。开发模式不注册 SW。`public/_redirects` 和顶层 `dist/404.html` 仍禁止加入。

`verify:sync` 使用 CDP 拦截假 Auth 与假云端，验收统一 UID、自动推送、断网保留队列、联网重验后补传、失败如实显示、退出/身份变化期间旧结果不能修改新工作区，以及两种手动整体替换。旧 local UID 与 cloud UID 分开的绑定流程不再是现行验收目标。

`verify:sql` 串行启动临时 PostgreSQL，真正执行迁移并验证表、RLS、GRANT、四个 RPC、门禁默认拒绝、允许 UID 与旧 UID 的访问边界、备份 v3 往返、历史日期豁免和子表跨 owner 关联拒绝。需要 PostgreSQL 16+，可用 `MOLLY_PG_BIN` 指定；缺依赖或失败即报告失败，不能静默跳过。它不连接生产 Supabase，不能证明托管 Auth、schema cache 或真实部署状态。

浏览器脚本结束会关闭自己的临时服务和浏览器。`CHROME_PATH` 可指定浏览器，`APP_URL` 可指定现有开发服务；设置 `SHOT_DIR` 可保留截图。需要核对真机行为时仍要在手机上执行人工验收。

## 人工验收

1. 配好可信 Auth 与 W 门禁后用 W 登录；错误密码必须失败，不出现注册或二次绑定入口。首次准备失败时不能进入业务页。
2. 准备明天的三餐、补剂、健身、晨间和自定义事项，刷新确认本地恢复；执行今天的勾选独立于准备状态。
3. 确认历史日期只读；复制昨天保留内容快照，不复制准备/完成状态，也不改目标日期模式。
4. 核对选项增改、排序、启停与删除、补剂实例化、正常休息日家务和临时不上班规则。
5. 生成 v3 备份并检查无密码/token；导入后当前 UID 的业务数据整体替换。非法或关联冲突的备份必须一条不写；v1/v2 仅恢复业务，不恢复旧身份。
6. 断网前打开已准备工作区，断网编辑应保存本地且队列保留；恢复网络重新校验身份后补传。退出再用原账号登录，本地资料、业务与待上传项应保留。
7. 确认样本已上传并保留独立备份后，在全新浏览器或测试设备用同一个 W 登录，应恢复原 Auth UID 下的云端数据。不能把从未上传且被清除的本地编辑当成可恢复数据。
8. 使用受控测试旧 UID/JWT 直接检查服务端读写及四个 RPC 被拒；登录界面只接受 W 不能代替这项 RLS 验证。生产旧数据去向和 UID 迁移另行盘点，不通过清空站点或删除 Auth 用户处理。
9. 在真实 HTTPS 域名核对首页、SPA 深链接、SW/manifest 的 `no-cache`、assets 的 `immutable`，以及新旧应用壳更新流程。
10. iOS Safari 添加到主屏幕，Android 检查安装流程，核对独立窗口、存储状态、软键盘、抽屉保存/取消和安全区。安装不能替代业务备份。

## 部署

按 [部署指南](DEPLOY.md) 和 [部署执行说明](docs/27-deploy-runbook-for-codex.md) 操作。先完成本地验收，核实真实项目迁移历史、W 的实际 Auth UID、旧数据去向与密码策略，再准备门禁及 Auth 配置，最后写入 Vercel 构建期变量并发布。

已有数据库只执行审核确认的缺失迁移；空库才使用完整合并迁移初始化。`npm run deploy` 只读核验数据库，不自动迁移或创建 W，其成功也不能代替登录、恢复、RLS 与真机验收。
