## 1. 当前结论

本地源码已经从“本地账号 + 可选云端绑定”改为“Supabase Auth 账号密码 + 统一 Auth UID”：

- 登录和重新登录均通过 Supabase Auth `signInWithPassword`。
- Supabase Auth 是唯一账号密码认证来源；本地资料与离线缓存不构成第二套认证。
- 本地不再校验 `users.password_hash`，不再公开注册，也不再提供二次绑定或补建云端身份入口。
- 活动工作区的业务记录、用户资料、同步状态和待上传队列均以当前 Supabase UID 作为归属。
- IndexedDB 仍是业务唯一写入落点；云端只承担认证、按 UID 的业务传输和整体替换。
- 首次登录会先验证当前 UID、恢复该 UID 的云端快照，再开放业务写入和自动上传。
- 普通退出只关闭当前设备工作区，保留本地记录与未上传队列；重新登录同一 UID 后继续使用。
- 旧本地身份、旧绑定、旧队列和工作区状态进入隔离仓库，不按账号名自动认领或删除。

生产展示账号为 `W`；输入 `W`/`w` 经归一化后只保留用户名 `W`。实际身份和授权由已验证的 Auth UID 与服务端 allowlist 决定，展示资料或旧账号同名不授权。真实项目的目标账号及 UID 尚未核验，准备时优先保留经确认的合法目标 UID。初始密码由用户在可信 Supabase Auth 管理入口设置，密码不写入源码、迁移、文档、种子数据、环境变量或前端比较逻辑。

## 3. 已落地的源码范围

### 3.1 认证生命周期

- `src/services/sync/authSession.ts` 负责 Supabase SDK 生命周期、会话验证、UID 门禁、首次恢复和退出。
- `src/services/api/authService.ts` 只提供认证门面，使用动态 import，避免把 Supabase SDK 打入首屏主块。
- `src/services/session.ts` 只保存已验证的运行时身份；历史 session JSON 仅作迁移线索，不能直接登录。
- 增加认证代次、工作区上下文和退出锁，防止旧异步结果写入新账号。
- SDK 事件在回调外异步处理；准备完成前和最终发布前都会再次核对 SDK UID。
- 用户元数据可留空，不作为登录或离线恢复条件；在线以 `getUser()` 和 `account_access()` 的许可及 UID 一致性放行。离线先核对已准备 owner，再检查工作区与资料归属。
- 迟到 `SIGNED_OUT` 会重新读取实际 SDK 会话；确认退出后关闭工作区并阻止缓存会话自动恢复。

### 3.2 IndexedDB 与备份

- 数据库版本升至 v8，当前共有 18 个仓库。
- 新增旧身份隔离、工作区状态和迁移 journal 仓库；v8 结构升级即清空活动旧资料、移除旧账号名唯一索引，隔离资料也不保留密码或身份 token。
- 活动 `sync_state`、`sync_outbox`、资料缓存和业务工作区统一按 Auth UID 归属；隔离旧业务保留原 owner。
- 备份格式升至 v3，兼容读取 v1/v2；备份不恢复认证会话，不保存密码。
- 导入先验证完整父链与同 owner 来源选项，再在同一事务内写入；名称快照不能掩盖跨 owner 引用。
- 普通导入保留 ID，拒绝覆盖其他 owner 或孤儿的同表主键。还检查保留记录的缺失父/来源引用，防止 incoming 补齐缺失计划、餐次或来源选项后把隔离数据重新接入当前账号；拒绝时零写入。
- 显式复制旧工作区对十张业务表完整换 ID，同步重映射五条计划子表、餐次父键及 food/exercise 来源选项。生成 ID 避开所有已有主键与有效引用值，`null` 来源保持为空，根表 `user_id` 不当业务引用。
- 缺失的旧来源选项可在只读快照中置为 `null` 并保留名称；原 owner、其他 owner、孤儿及旧队列原地保留，不按 W 同名自动认领。
- 空云端初始化不会播种示例覆盖已有业务；未上传编辑和上传中新增队列保留。

### 3.3 同步和整体替换

- 推送只读取当前 UID 的队列和主表记录，删除先于 upsert，失败按整批处理。
- 工作区未准备完成、没有有效会话或 owner 为 `null` 时不上传。
- 增量上传、云端恢复、整体上传和整体恢复均检查固定 `{ owner, generation }` 上下文。
- 退出或身份变化后，迟到响应不能更新本地状态、错误提示、队列或同步时间。
- 云端摘要、快照和替换 RPC 失败时不降级成“云端为空”。

### 3.4 数据库迁移

新增：

`database/migrations/20261011183805_account_identity_gate.sql`

该迁移建立私有单 UID allowlist，默认拒绝未配置身份；为 12 张公开表（十张业务表、`profiles`、`sync_test_records`）增加 restrictive UID 门禁，补充最小 GRANT，并保护四个认证/同步 RPC。allowlist 的 singleton 约束至多允许一条目标 UID，迁移不包含账号、密码或 UID 种子值；生产 UID 必须在可信管理入口核验后再写入。

四个公开 RPC `account_access`、`cloud_sync_summary`、`export_cloud_snapshot`、`import_local_backup` 均为 `security invoker`。唯一受限的 `security definer` 查询是私有 `private.is_account_allowed()`，它不接受调用者指定 UID，只读取当前 `auth.uid()` 的 allowlist 资格，不读取业务数据。`profiles` 只授予 select/update，其余公开表按业务需要提供 CRUD，门禁与原有 owner RLS 同时生效。

合并部署文件 `deploy/supabase-all-migrations.sql` 已包含七个迁移，但真实项目不能盲目重复执行整份文件。部署前必须核对 migration history，只执行缺失迁移；完整合并文件只适用于空项目初始化。

## 6. 数据清理和回退边界

旧业务数据默认隔离保留，不自动迁入 W，也不因为只保留一个展示账号就删除。需要迁入时，先完成每个旧 owner 的数据清单、备份、冲突预览和恢复演练，再按批准的映射执行。

删除旧 Auth 用户前必须确认其业务数据已迁移或明确放弃，因为 Auth 删除可能触发业务数据级联删除；已签发 access token 也不会立即失效。回退源码不等于回退数据库、Auth 用户或设备本地数据。

## 8. 已知限制

Supabase SDK 的跨标签共享会话仍可能在旧标签执行 logout 后移除新标签的共享会话。应用会检测实际会话并要求重新登录，不伪造 `ready`；本轮没有另行实现跨标签 SDK 锁。

离线缓存只能表示此前已完成认证并准备过的 UID 工作区。首次登录、主动退出或明确 token 撤销后，不使用旧 JSON 或自制密码离线放行。
