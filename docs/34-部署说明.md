# 幸福小Molly 部署说明

## 架构

```text
Cloudflare 现有域名
  └─ DNS + HTTPS + 代理加速
       └─ Vercel 生产站点
            └─ Supabase 云端能力
```

- 前端构建与生产发布：Vercel。
- 域名、DNS、HTTPS 和边缘代理：Cloudflare。
- 用户数据写入：浏览器 IndexedDB；Supabase 只提供可选云端上行能力。
- Cloudflare 不创建 Pages 项目，也不保存前端构建产物。
- 前端只使用 Supabase anon/publishable key，绝不使用 `service_role`。

## 首次接入

1. 在 Vercel 项目中确认生产部署可访问，并添加自定义域名。
2. 在 Cloudflare 控制台读取已有 Zone 和 DNS 记录，选定用于本应用的主机名。
3. 按 Vercel 给出的目标记录，在 Cloudflare 添加或调整该主机名的 DNS 记录。
4. 新 CNAME 先设为“仅 DNS”，等待 Vercel 域名与证书验证通过；再开启 Cloudflare 代理，并核对 SSL/TLS 为 Full (strict)。
5. 在 Supabase Auth 的 URL Configuration 中加入最终 Cloudflare 域名：
   - `Site URL`：应用正式地址。
   - `Redirect URLs`：应用正式地址及必要的回调路径。
6. 用正式域名验证首页、深链接、Service Worker、manifest 和静态资源缓存；不要对 HTML、`/sw.js` 或 manifest 使用“缓存所有内容”规则。
7. 用中国大陆的实际手机网络验证首页、登录、云端请求、离线与 PWA 更新。

DNS 修改前必须确认目标域名和现有记录，不能覆盖不相关的邮箱、验证或其他业务记录。

## 上线自检

对 Vercel 地址和 Cloudflare 正式域名各执行一次：

- 首页返回 HTTP 200。
- 页面标题为“幸福小Molly”。
- `/sw.js` 和 `/manifest.webmanifest` 不使用长缓存。
- `/assets/*.js` 使用带哈希资源的长期缓存。
- 任意应用深链接返回 HTTP 200。
- iPhone Safari 中字体、卡片文字、底部导航和 PWA 交互正常。

## 回滚

回滚只操作 Vercel：将上一个 `READY` 部署重新提升为生产版本。Cloudflare 的 DNS 和代理
记录保持不变，正式域名会继续访问回滚后的 Vercel 版本。

Supabase 迁移只向前兼容，不通过回滚前端来伪装回滚数据库结构。涉及数据库变更时，先
执行并验证迁移，再发布依赖新字段的前端版本。
