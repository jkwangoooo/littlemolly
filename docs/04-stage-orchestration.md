# 幸福小Molly：阶段实施与验收协议

## 总指挥规则

- 本项目采用 React + TypeScript + Vite 前端，Supabase Auth + PostgreSQL + RLS 云端服务。
- 每个开发阶段由独立窗口实施；新窗口只能处理被分配阶段，不得提前实现后续业务。
- 实施前必须阅读 `HANDOFF.md`、`docs/00-product-scope.md`、`docs/01-architecture-data-contract.md`、`docs/02-ui-interaction-spec.md`、`docs/03-delivery-roadmap.md`，以及本文件对应阶段提示词。
- 实施前检查 Git 状态并保留既有改动；不使用覆盖式或破坏性 Git 操作。
- 所有数据库迁移只追加，所有用户数据表启用 RLS。禁止用 `localStorage` 冒充云端同步。
- 阶段完成后，实施窗口必须更新 `HANDOFF.md`，提供命令/浏览器验证证据、未验证项、下一步和精确文件清单。
- 总指挥只在当前阶段通过验收并记录后，才发放下一阶段提示词。

## 阶段 1 总指挥验收清单

新窗口结束后，必须同时满足以下条件才可进入阶段 2：

1. 工程使用 React + TypeScript + Vite，目录责任未混入业务代码。
2. 认证可用，会话刷新后仍正确恢复或清除。
3. 迁移可从空库执行，包含 `profiles` 与用户私有测试表。
4. 用户私有表明确启用 RLS，策略限制到 `auth.uid()`；不能只依赖前端过滤。
5. 测试记录通过真实 Supabase 写入并在刷新后读取回来。
6. 保存 UI 有保存中、成功、失败三种可见状态；失败不显示成功。
7. 通过构建/类型检查和实际桌面、手机浏览器验证。
8. `HANDOFF.md` 已写明已验证事实、未验证项和下一步。

如果第 5 或第 7 项因缺少 Supabase 凭据而无法完成，阶段 1 状态为“部分完成，等待云端验收”，不得开始阶段 2。
