# 幸福小Molly：第三阶段 UI 交互设计执行文档

> 本文是第三阶段 UI 交互改造的执行依据，不是灵感清单。
> 执行代理必须先读本文，再读 `AGENTS.md`、`docs/26-S6-handoff-for-codex.md`、`docs/02-ui-interaction-spec.md`、
> `docs/11-L4-completion-report.md`、`docs/16-pwa-shell-completion-report.md` 和
> `docs/17-options-page-ia-research.md`。
>
> 本阶段目标是升级今日页的核心体验。它不是配色重做、导航重做、数据模型重做，也不是增加业务功能。

## 1. 阶段目标

### 1.1 一句话目标

把今日页从「查看和勾选事项的列表」改造成：

> **沿着今天的节奏前进：有一条可读的剧情轨道，有一个明确的当前焦点，有一个不制造压力的小火伙伴。**

### 1.2 用户体验目标

用户打开今日页后，应当在几秒内知道：

1. 今天是什么模式：工作日还是休息日。
2. 当前最值得处理的一件事是什么。
3. 后面还有哪些节点。
4. 哪些事项已经完成。
5. 哪些事项还没有安排。
6. 完成后页面和小火发生了什么变化。

用户不能产生以下困惑：

- 「这是另一种普通待办列表吗？」
- 「这个事项是没有安排，还是已经完成？」
- 「我必须按顺序做吗？」
- 「滑动后到底保存成功了吗？」
- 「小火是在鼓励我，还是在催我打卡？」

### 1.3 已锁定的产品决策

以下决策不得在执行过程中擅自改动：

| 议题 | 已锁定结论 |
| --- | --- |
| 主交互 | 纵向剧情轨道 + 当前事项焦点卡 |
| 推进关系 | 软顺序：突出下一项，但不锁死其他事项 |
| 完成动作 | 点击为主，滑动为快捷方式 |
| 轨道顺序 | 按日常节奏锚点，不伪造精确时间 |
| 未准备事项 | 保留节点但弱化，可进入安排 / 编辑 |
| 执行状态 | 不增加开始中、暂停、进行中、计时等新业务状态 |
| Molly 角色 | 今日页持续可见的状态伙伴 |
| Molly 形象 | 可爱的小火，使用矢量资产 |
| 小火含义 | 当天能量，不代表连续打卡、排名或 streak |
| 小火出现范围 | 只出现在今日页 |
| 主用户 | 个人长期使用，不以短期游戏化留存为目标 |
| 手势替代 | 任何滑动动作都必须有点击、按钮和键盘等替代路径 |

- 今日页的布局与视觉层级。
- 今日页的轨道节点呈现。
- 当前焦点卡及其完成反馈。
- 今日页的轻量小火视觉状态。

- 今日页相关的纯 UI 视图模型。
- 今日页相关的浏览器验收断言和局部样式。

### 2.2 本阶段禁止改动

- 不新增数据库字段、对象仓库、索引、迁移或备份格式。
- 不改变 `DayPlan`、三餐、补剂、健身、自定义事项的既有业务语义。
- 不新增「开始中」「暂停」「延期」「跳过」「计时」等持久化状态。
- 不新增提醒、通知、连续打卡、排行榜、奖励系统等业务。
- 不改动本地 IndexedDB 是唯一写入落点的原则。
- 不改动云端同步协议、同步文案和服务层边界。
- 不改动「今日 / 本周 / 选项」底部一级导航。

- 不把今日页改成精确日历或时间管理工具。
- 不把滑动做成唯一完成路径。
- 不用动画或占位文案伪装本地保存、云端同步或成功状态。

## 3. 当前代码事实

当前今日页由 `src/features/day-plan/DayPlanScreen.tsx` 编排，相关展示组件包括：

- `components/NextAction.tsx`
- `components/ExecuteList.tsx`
- `components/PrepList.tsx`
- `components/RoutineList.tsx`
- `components/CustomTaskList.tsx`
- `components/ModeCard.tsx`
- `components/SaveStatusBar.tsx`

现有数据状态的关键事实：

- 准备项是 `outfit_ready`、`meals_ready`、`supplements_ready`、`morning_ready`、`exercise_ready` 五个布尔值。
- 执行完成状态分别存在于晨间、三餐、补剂、健身、自定义事项和休息日家务记录中。
- 自定义事项有 `task_time`，内置事项没有完整的精确时间字段。
- `DayPlan` 有 `work` / `rest` 模式和健身决定状态。
- 历史日期必须保持只读。
- 当前 `NextAction` 已经提供了「找出第一项未完成事项」的基础逻辑。
- 当前编辑必须继续通过现有 `EditorSheet` 和 `src/services/api/` 门面完成。

因此，本阶段应优先做一个纯函数视图投影层，而不是扩展服务层。

## 4. 目标交互模型

### 4.1 轨道不是精确时间轴

轨道表达的是「今天的节奏」，不是承诺每个事项有准确发生时间。

工作日执行轨道的默认语义顺序：

1. 晨间事项。
2. 早餐。
3. 早间补剂。
4. 午餐。
5. 午间补剂。
6. 健身。
7. 晚餐。
8. 晚间补剂。
9. 自定义事项旁线。

说明：

- 某个内置事项没有内容时，显示为弱化的未准备节点，而不是伪造时间。
- 已安排的补剂可以按已有时段拆成节点；没有任何已安排补剂时，只显示一个「补剂尚未安排」的弱化节点。
- 自定义事项继续按 `task_time` 升序显示，但不得为了插入主轨道而给内置事项硬塞时间。
- 健身没有精确时间时，放在午餐之后、晚餐之前的语义位置；用户仍可以随时点击完成。
- 健身决定为「不健身」时，不显示为待完成事项；保留轻量说明即可。

休息日执行轨道：

1. 拖地。
2. 洗衣。
3. 已安排补剂。
4. 健身。
5. 自定义事项旁线。

临时切换为休息日且 `mode_override === true` 时，不自动显示拖地和洗衣。

### 4.2 准备明天轨道

「准备明天」继续是独立场景，不和今日执行混在一条轨道内。

五个节点固定为：

1. 衣服已经准备好。
2. 三餐已安排。
3. 早中晚补剂已安排。
4. 晨间事项已安排。
5. 健身安排已决定。

其中：

- 衣服只有勾选动作。
- 三餐、补剂、晨间、健身节点可以进入对应编辑面板。
- 准备进度继续使用现有五项布尔值。
- 准备完成不改变小火的当天能量状态。

### 4.3 轨道节点状态

建议建立纯 UI 类型，不写入数据库：

```ts
type TodayRouteNodeState =
  | 'unprepared'
  | 'current'
  | 'upcoming'
  | 'completed'
  | 'readonly'

type TodayRouteNodeKind =
  | 'morning'
  | 'meal'
  | 'supplement'
  | 'exercise'
  | 'routine'
  | 'custom-task'
  | 'prep'

interface TodayRouteNode {
  id: string
  kind: TodayRouteNodeKind
  title: string
  detail?: string
  state: TodayRouteNodeState
  editable: boolean
  completionTarget?: string
  editorTarget?: string
}
```

实际命名可以按代码库现有风格调整，但必须保留以上语义。

### 4.4 当前焦点选择规则

今日执行场景下，当前焦点按以下优先级产生：

1. 第一个需要安排的 `unprepared` 节点，显示动作「去安排」。
2. 如果没有未准备节点，则取轨道中第一个未完成的已安排节点。
3. 如果所有已安排节点都完成，则显示「今天安排都完成了」。

准备明天场景下：

1. 取第一个未勾选准备节点。
2. 五项全部勾选后显示准备完成状态。

软顺序要求：

- 当前焦点只是视觉引导，不是锁。
- 用户可以点击任何其他节点查看、编辑或完成。
- 未准备节点不能通过完成按钮伪装成执行完成。

## 5. 当前焦点卡交互

### 5.1 主操作

- 点击「完成」调用当前已有的完成保存路径。
- 保存成功后，节点状态才改变，小火状态才更新。
- 保存中显示明确的保存中状态，避免重复提交。
- 保存失败时保留原状态，使用已有错误反馈，不播放成功反馈。
- 再次点击已完成节点可以撤销完成，继续走现有 API。

### 5.2 滑动快捷完成

只在当前焦点卡上实现，不在整页捕获：

- 从左向右滑动，等同于点击「完成」。
- 建议水平位移达到 `72px` 且水平位移大于垂直位移时触发。
- 历史日期、只读状态、保存中和不可完成节点不响应滑动。
- 向左滑动不绑定任何新业务。
- 滑动触发后仍然必须等待真实保存成功。
- 必须保留按钮、点击和键盘操作。

### 5.3 编辑入口

- 已安排的三餐节点进入三餐编辑面板。
- 补剂节点进入补剂编辑面板。
- 晨间节点进入晨间编辑面板。
- 健身节点进入健身编辑面板。
- 自定义事项进入现有自定义事项编辑面板。
- 未准备节点的主按钮文案使用「去安排」或等价明确文案。
- 历史日期不显示编辑入口。

## 6. 小火状态系统

### 6.1 状态来源

小火状态只由当前日期的 UI 投影计算，不新增数据库字段。

完成比例只统计「已安排且可执行」的节点：

- `unprepared` 不计入分母。
- 被模式排除的事项不计入分母。
- 休息日没有可执行事项时，不显示负面状态。

建议状态：

| 状态 | 条件 | 视觉语义 |
| --- | --- | --- |
| `quiet` | 没有完成事项，或没有可执行事项 | 安静燃烧 |
| `glow` | 已完成少量事项 | 开始有能量 |
| `bright` | 已完成至少一半但未全部完成 | 状态明亮 |
| `settled` | 所有可执行事项完成 | 今天安定下来 |

不得显示数值能量、连续天数、排名或「落后」类文案。

### 6.2 角色表现

- 使用矢量小火资产。
- 角色尺寸必须稳定，不能因文案或状态变化挤压轨道布局。
- 动画以短促、低干扰反馈为主，不持续闪烁。
- 完成反馈只在本地保存成功后触发。
- 休息日允许呈现安静、柔和状态，不把休息解释成失败。
- 历史日期使用安静的只读表现，不模拟实时陪伴。

## 7. 建议实现拆分

### 第一步：建立纯函数视图投影

新增或整理今日页内部的 route builder：

- 输入现有 `DayPlan`、三餐、餐项、补剂、健身、家务、自定义事项、日期关系和当前场景。
- 输出节点数组、当前焦点、可执行节点数量和小火状态。
- 不读写 IndexedDB。
- 不调用云端。
- 不修改数据服务。

优先复用 `getExecuteActionItems` 和 `getPrepActionItems` 的既有语义，避免重新定义完成目标。

### 第二步：替换今日页展示层

建议新增以下展示责任：

- `TodayStage`：今日页舞台容器。
- `TodayRoute`：轨道和节点。
- `TodayFocusCard`：当前焦点卡。
- `MollyFire`：小火状态展示。

可以重构或替换 `NextAction`、`ExecuteList`、`RoutineList` 和 `CustomTaskList` 的展示方式，但必须保留：

- 编辑入口。
- 删除入口。
- 历史只读。
- 空状态。
- 保存状态。
- 错误重试。

### 第三步：接入手势和反馈

- 只给当前焦点卡增加滑动快捷完成。
- 点击、滑动必须复用同一个完成回调。
- 不在组件内复制保存逻辑。
- 不做乐观成功动画。
- 不改变 `useSaveRunner` 的真实保存语义。

### 第四步：小火资产和视觉校准

- 使用矢量资产，不使用新增位图依赖。
- 小火只在今日页渲染。
- 先保证布局稳定，再增加状态动画。
- 手机端优先验证，桌面端保持现有 760px 内容宽度和居中布局。

## 8. 验收场景

执行代理必须至少验证：

1. 工作日完整计划能按轨道顺序显示。
2. 工作日缺少三餐、晨间、补剂或健身安排时，节点弱化且可进入安排。
3. 当前焦点始终遵守「先安排，再执行」规则。
4. 点击完成后，真实保存成功才进入完成状态。
5. 右滑和点击调用同一完成逻辑。
6. 保存失败时不显示成功状态，不改变小火状态。
7. 完成节点可以点击撤销。
8. 休息日正常显示拖地、洗衣，临时休息日不显示自动家务。
9. 历史日期所有节点只读，不响应完成和滑动。
10. 自定义事项保留时间排序、编辑和删除。
11. 准备明天保持独立五节点轨道。
12. 空白未来日期不凭空生成大量事项。
13. 小火不出现在周视图和选项页。
14. 手机端无横向溢出，底部导航和安全区不被遮挡。
15. 键盘和按钮可以完成所有滑动能完成的动作。
16. 控制台无新增 error / warning。
