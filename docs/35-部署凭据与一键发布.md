# 部署凭据与一键发布

## 首次配置

在项目目录执行：

```bash
npm run deploy:setup
```

按提示依次输入：

- `VERCEL_TOKEN`：Vercel 账户的 Personal Token，只用于 CLI 部署。
- `SUPABASE_DB_URL`：Supabase 的 PostgreSQL URI，只用于执行迁移和结构验证。
- `VITE_SUPABASE_URL`：Supabase Project URL。
- `VITE_SUPABASE_ANON_KEY`：Supabase anon/public key。

脚本会把凭据保存到当前 Windows 用户目录：

```text
%USERPROFILE%\.happy-little-molly\deploy.env
```

该文件不在项目目录内，不会进入 Git，也不会被 Vercel 上传。保存后不要把文件内容提交或发到聊天中。`service_role` 不属于部署凭据，禁止录入。

首次配置会优先复用项目 `.env.local` 中已有的 Supabase URL / anon key，只提示缺少的凭据。
如需更换某项凭据，执行 `npm run deploy:setup -- --force`；已有值会重新提示，回车可保留。

## 后续发布

以后版本更新完成后，在项目目录执行：

```bash
npm run deploy
```

也可以直接对 Codex 说：**部署最新版本**。标准流程会自动执行：

1. `typecheck`、`lint`、`build` 和 `verify:pwa`。
2. 幂等执行 Supabase 合并迁移。
3. 刷新 PostgREST schema cache。
4. 验证 Supabase 的 12 张表、3 个 RPC、21 条 RLS 策略。
5. 更新 Vercel production 的两个 `VITE_*` 构建变量。
6. 部署 Vercel production。
7. 检查线上首页、SPA 深链接、Service Worker/Manifest 缓存头和 Assets 长缓存。

任何一步失败都会停止，脚本不会报告“已上线”。

## 凭据安全

- 凭据文件默认位于用户目录，权限按 Windows 用户账户保护；脚本同时尝试设置仅所有者可读权限。
- 可以通过环境变量 `MOLLY_DEPLOY_CONFIG` 指定其他凭据文件路径，但该路径应放在项目目录之外。
- 只读输出部署状态，不打印 Token、数据库密码或 anon key。
- `VITE_SUPABASE_ANON_KEY` 会进入浏览器构建产物，这是 Supabase anon key 的正常使用方式；数据库连接串和 Vercel Token 不会进入构建产物。
- 迁移文件必须保持幂等；部署脚本重复执行不会清空业务数据。
