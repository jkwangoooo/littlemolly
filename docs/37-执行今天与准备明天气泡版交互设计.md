## 1. 设计目标

### 1.1 核心体验

把今日页从规整清单改成一个可探索、可聚焦的“今日节奏空间”：

- 用户打开后先理解今天的执行进度。
- 固定事项以节奏节点呈现，不被误解为精确时间线。
- 有时间的自定义事项可以自然进入空间，但不强行归入固定分组。
- 无时间的自定义事项仍然有完整入口，不被视觉布局隐藏。
- 执行和准备是两个明确的一级任务，不再依赖含义模糊的通用导航名称。

### 1.2 产品边界

本方案只调整今日页的导航、布局和交互呈现：

- 不新增数据库字段、对象仓库、索引、迁移或备份格式。
- 不改变三餐、补剂、晨间事项、健身、自定义事项的既有业务语义。
- 不把“安排完成”当作“执行完成”。
- 不增加“开始中”“暂停”“延期”“跳过”“计时”等持久化状态。
- 不把气泡位置解释成内置事项的精确发生时间。
- 本地保存、云端上行和失败文案继续遵守现有规范。

## 2. 一级信息架构

### 2.1 底部双入口

底部固定两个主入口：

1. **执行今天**：处理今天实际要完成的事项。
2. **准备明天**：安排明天将要执行的内容。

不再在底部显示“今日 / 本周 / 选项”作为当前主场景的入口文案，也不使用“文档”类名称承载日程功能。

底部入口必须满足：

- 两个入口拥有相同的视觉权重。
- 当前入口使用强调色、图标填充或短横线表达选中状态。
- 非当前入口显示轻量预览信息，但不混入另一场景的操作控件。
- 两个入口触控区域足够大，适合单手点击。
- 底部安全区不能遮挡气泡或详情面板。

### 2.2 两个场景的语义分离

| 场景 | 处理对象 | 主要状态文案 | 主动作 |
| --- | --- | --- | --- |
| 执行今天 | 今天已经安排的实例 | 已完成、现在完成、待完成、尚未安排 | 完成今天这一项 |
| 准备明天 | 明天的五项准备 | 已安排、尚未安排、还差 N 项 | 去安排、编辑、确认 |

切换入口时，页面标题、进度数字、气泡状态和主操作一起切换。不能只替换标题而保留上一场景的完成语义。

## 3. 执行今天版面

### 3.1 页面层级

从上到下：

1. 应用名称：幸福小Molly。
2. 页面标题：执行今天。
3. 日期与模式：例如“今天 · 9月30日 · 星期三 / 工作日”。
4. 总进度：例如“4 / 8”，并补充“还剩 4 件”。
5. 今日节奏空间：固定事项与有时间的自定义事项。
6. 当前行动提示：只强调当前最值得处理的一项，不锁死其他事项。
7. 无时间自定义事项入口：我的事项。
8. 底部双入口：执行今天 / 准备明天。

### 3.2 节奏空间

节奏空间不是时间线，也不是规则网格。它使用轻微不对称的节点布局表达一天的节奏：

- 晨间、午间、晚间是视觉参考区域，不是新的数据分类。
- 固定事项按真实业务顺序形成视觉节奏：晨间事项、早餐、早间补剂、午餐、午间补剂、健身、晚餐、晚间补剂。
- 当前事项节点可稍大，并使用强调色环或轻微呼吸效果。
- 已完成节点缩小或降低对比度，但保留标题和状态。
- 待完成节点保持可见，不能因为未完成而被隐藏。
- 尚未安排节点使用虚线轮廓或浅色状态，禁止显示“完成”操作。
- 不使用贯穿整个页面的竖线，不制作传统时间轴列表。

固定事项没有精确时间时，只表达节奏顺序，不伪造时间标签。

### 3.3 固定事项顺序

工作日执行顺序：

1. 晨间事项。
2. 早餐。
3. 早间补剂。
4. 午餐。
5. 午间补剂。
6. 健身。
7. 晚餐。
8. 晚间补剂。

休息日保留现有休息日业务规则：正常周末自动出现拖地、洗衣；临时不上班不自动加入家务；补剂、健身和自定义事项仍然可以执行。

### 3.4 当前事项规则

当前事项只用于视觉引导，不是强制顺序：

1. 如果存在尚未安排且需要用户处理的事项，优先提示“去安排”。
2. 没有尚未安排事项时，聚焦第一个未完成的已安排事项。
3. 所有可执行事项完成后，显示“今天安排都完成了”。
4. 用户可以直接短按其他气泡查看详情，也可以长按其他待完成气泡完成它。
5. 未安排事项不能通过长按变成执行完成；必须先进入安排或编辑流程。

## 4. 自定义事项气泡

### 4.1 有时间的自定义事项

自定义事项包含明确时间时，按 `task_time` 参与节奏空间的布局：

```text
        早餐 ✓

晨间事项 ✓       早间补剂 ◉

              10:30
          整理房间 ○

        午餐 ○
```

这里的时间只作为用户设置的事项时间锚点，不代表固定事项也具备精确时间。

视觉表现建议：

- 使用与固定事项不同的气泡轮廓，例如菱形、双线环或带小标签的圆点。
- 气泡旁显示时间和标题，例如“10:30 · 整理房间”。
- 自定义标记必须同时配合文字或图形，不得只靠颜色区分。
- 自定义事项可以出现在固定节点之间，不能因为时间不符合晨间/午间/晚间而被强行改写。
- 事项排序以时间升序为基础；相同时间按创建顺序稳定排列。

### 4.2 没有时间的自定义事项

没有设置时间的事项不强行插入节奏空间，统一进入“我的事项”入口：

```text
我的事项 · 2 项

整理房间       待完成
回复消息       已完成
```

入口可以采用轻量抽屉或底部展开层，但不能做成一个套着多个卡片的卡片墙。

打开后必须支持：

- 查看所有自定义事项。
- 按未完成 / 已完成筛选。
- 编辑时间、名称和备注。
- 完成和撤销完成。
- 删除并二次确认。

### 4.3 自定义事项较多时

主节奏空间只显示有限数量的摘要气泡，避免遮挡和误触：

- 优先显示当前未完成且有时间的事项。
- 其余事项收纳为“+N 项自定义事项”。
- 点击“+N 项自定义事项”打开完整的我的事项抽屉。
- 所有事项仍保留在完整数据和完整列表中，不能因主视图限制而丢失。

## 5. 气泡状态

### 5.1 状态语义

| 状态 | 气泡表现 | 文案 | 可用交互 |
| --- | --- | --- | --- |
| 尚未安排 | 浅色虚线轮廓 | 尚未安排 | 短按进入安排；不可长按完成 |
| 待完成 | 空心圆或轻量轮廓 | 待完成 | 短按详情；长按完成 |
| 当前 | 强调色环、稍大节点 | 现在完成 | 短按详情；长按完成 |
| 已完成 | 勾号、绿色弱化节点 | 已完成 | 短按详情；长按撤销或打开详情 |
| 只读 | 横线或低对比节点 | 只读 | 短按查看；不允许写入 |
| 保存失败 | 错误标记 | 重试 | 短按打开错误详情或重试 |

颜色不是唯一状态表达。每个状态必须同时具备图形、文字或位置变化中的至少两种表达。

### 5.2 计划与执行的区分

以下状态不能混用：

- 三餐“已安排”不等于早餐、午餐、晚餐“已完成”。
- 补剂“已安排”不等于早间、午间、晚间补剂“已完成”。
- 健身“已决定”不等于健身“已完成”。
- 自定义事项时间存在不等于自定义事项已完成。

## 6. 核心手势交互

### 6.1 短按：打开事件详情

短按气泡的唯一默认动作是打开该事件详情，不直接完成。

判定原则：

- 指针按下后在短时间内释放，且移动距离未超过点击容差，判定为短按。
- 短按不触发完成写入。
- 短按后打开底部详情面板或现有 `EditorSheet` 对应的详情态。
- 面板标题显示事项名称、事项类型和当前状态。
- 有时间的自定义事项显示时间；无时间事项显示“未设置时间”。
- 可编辑事项显示编辑入口；只读日期只显示查看信息。

详情面板示例：

```text
整理房间
10:30 · 我的事项
待完成

打扫卧室和书桌

[完成]    [编辑]
```

短按打开详情后，用户仍可以通过面板中的明确按钮完成，保证长按不是唯一完成路径。

### 6.2 长按：完成操作

长按待完成气泡表示“完成这一项”的快捷操作。

建议判定参数：

- 长按触发阈值：`500ms` 左右。
- 触发前允许的移动容差：不超过 `10px`。
- 触发时提供触觉反馈（设备支持时）和视觉反馈。
- 触发后显示轻量确认动画，但只有保存成功后才改变为已完成状态。
- 保存期间显示“保存中”，防止重复触发。

长按流程：

1. 用户按住待完成气泡。
2. 气泡显示按压进度或外圈收拢，提示当前正在识别长按。
3. 达到阈值后触发完成意图，并给出一次短促触觉反馈。
4. 调用现有完成保存路径。
5. 保存成功：气泡变为绿色勾号，文案变为“已完成”，进度更新。
6. 保存失败：气泡回到原状态，显示“保存失败 / 重试”，不得伪装成已完成。

### 6.3 长按已完成事项

已完成气泡的长按不直接静默撤销，避免误触造成数据回退：

- 长按已完成气泡时显示“松开以撤销”提示。
- 用户松开后打开撤销确认或详情面板，由用户明确确认撤销。
- 不得因为一次误长按就直接清除完成状态。

### 6.4 尚未安排事项的长按

尚未安排气泡不能执行完成：

- 长按到达阈值时不写入完成状态。
- 显示轻量提示“请先安排此事项”。
- 短按仍然进入对应安排或编辑面板。

### 6.5 手势降级与可访问性

长按必须有显式替代路径：

- 详情面板提供“完成”按钮。
- 详情面板提供“撤销完成”按钮（仅已完成事项）。
- 键盘或辅助技术焦点进入气泡后，使用 Enter / Space 打开详情，详情内使用按钮完成。
- 触控设备不支持触觉反馈时，使用视觉反馈和状态文案替代。
- 不依赖颜色、动画或声音判断是否完成。

## 7. 准备明天版面

### 7.1 版面语义

准备明天不是执行页的另一组待办，而是“搭建明天”的准备空间。底部切换后，页面内容完全改为明天日期和五项准备状态。

固定五项：

1. 衣服已经准备好。
2. 三餐已安排。
3. 早中晚补剂已安排。
4. 晨间事项已安排。
5. 健身安排已决定。

### 7.2 准备气泡

准备气泡可以使用较大的拼图式节点或五个不规则模块，但不显示执行页的“待完成 / 已完成”语义：

- 未安排：尚未安排 / 去安排。
- 已安排：已安排 / 查看或编辑。
- 五项全部完成：明天已准备好。

准备气泡的短按行为：

- 衣服：打开准备确认详情。
- 三餐、补剂、晨间事项、健身：打开对应编辑面板。

准备气泡不使用执行页“长按完成”作为主要操作，避免把“安排”与“执行”混淆。若后续需要长按快捷勾选衣服，必须单独设计确认反馈，不能复用执行事项的完成写入语义。

### 7.3 准备进度

进度严格按五项准备布尔值计算：

```text
已准备 3 / 5
还差 2 项准备
```

五项完成后显示完成反馈，但不改变执行页当天事项的完成状态，也不改变当天能量状态。

## 8. 视图模型建议

气泡只是 UI 投影，不新增持久化状态。建议在今日页附近建立纯函数视图模型：

```ts
type RhythmBubbleState =
  | 'unprepared'
  | 'current'
  | 'upcoming'
  | 'completed'
  | 'readonly'
  | 'save-error'

type RhythmBubbleKind =
  | 'morning'
  | 'meal'
  | 'supplement'
  | 'exercise'
  | 'routine'
  | 'custom-task'
  | 'prep'

interface RhythmBubble {
  id: string
  kind: RhythmBubbleKind
  title: string
  detail?: string
  taskTime?: string
  state: RhythmBubbleState
  editable: boolean
  canComplete: boolean
  completionTarget?: string
  editorTarget?: string
}
```

视图模型要求：

- 自定义事项使用现有 `task_time` 排序。
- 内置事项没有精确时间时不生成虚假时间。
- `canComplete === false` 的气泡不能响应长按完成。
- 历史日期统一投影为 `readonly`。
- 保存错误只反映真实错误，不用乐观成功文案替代。
- 位置、大小、轮廓是视觉属性，不写入数据层。

## 9. 交互反馈与异常

### 9.1 保存成功

完成写入成功后：

- 更新气泡状态和进度数字。
- 显示“已完成”或“已撤销”。
- 如有小火伙伴动效，只表示本地完成反馈，不暗示云端同步成功。

### 9.2 保存失败

完成写入失败时：

- 保持原状态。
- 显示“保存失败，请重试”。
- 提供重试入口。
- 不显示绿色勾号，不更新完成进度。

### 9.3 云端状态

本地保存成功与云端同步状态继续分开表达：

- 本地保存成功：可以显示“已保存”。
- 云端上行失败：显示真实的云端失败或待重试状态。
- 不使用“已同步”作为队列排空或本地保存的替代说法。

## 10. 验收标准

### 导航

- 底部只有“执行今天”和“准备明天”两个主入口。
- 两个入口可独立切换，切换后日期、进度和内容语义正确。
- 当前入口状态清晰，另一入口不会混入当前场景的操作内容。

### 节奏空间

- 不出现贯穿页面的传统时间线。
- 固定事项按业务顺序呈现，视觉布局允许轻微不对称。
- 有时间的自定义事项按 `task_time` 作为时间锚点参与布局。
- 无时间的自定义事项可在“我的事项”中完整查看。
- 自定义事项数量增加时不会丢失、遮挡或无法访问。

### 手势

- 短按气泡打开详情，不直接完成。
- 待完成气泡长按可以触发完成。
- 长按完成只有在保存成功后才显示已完成。
- 尚未安排事项长按不会伪装为已完成。
- 已完成事项长按不会静默撤销。
- 详情面板存在完成按钮，作为长按替代路径。

### 业务一致性

- 三餐安排状态与三餐执行状态分离。
- 补剂安排状态与各时段补剂执行状态分离。
- 健身决定状态与健身完成状态分离。
- 历史日期保持只读。
- 本地优先写入和云端状态文案符合现有项目硬规则。
