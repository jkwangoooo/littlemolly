# 工作日转休息日：庆祝动效执行方案

> 状态：方案已确定，尚未实施。记录日期：2026-09-24。
> 本文供新对话的执行工程师直接接手。先做独立演示、确认效果，再接入正式程序。
> 用户已选定 **A「假日揭幕」+ B「日程松绑」**，核心是保存成功后的全屏彩带庆祝，而不是一般的按钮反馈。

## 1. 一句话目标

用户主动把某个可编辑的**工作日改为休息日**，确认且本地保存成功后，看到一次有情绪起伏的短演出：
工作日卡片退场、叠放卡片松开、全屏彩带从两侧爆发，休息日卡片落定。动画结束后是**真实的休息日页面**。

这是一条明确的好消息反馈，不是完成事项的通用动效，也不是积分、连续打卡或成就系统。
演出不代表云端同步成功。

### 2.1 当前源码事实

- 目前点击「确认切换」会立即关闭确认框，再调用
  `savePlan({ mode: next, mode_override: true })`。
- `savePlan` 把 `upsertDayPlan` 放进 `runSave`；页面通过 `src/services/api/dayPlanService` 写入。
- `runSave` **捕获异常但返回 `Promise<void>`**。因此 `await savePlan(...)` 正常返回，
  **不等于**保存成功；更不能根据某次全局 `status === 'saved'` 断言这次模式切换成功。
- `resetForDateChange` 会清除待重试动作和提示，但**不会取消正在执行的异步写入**；
  当前 `savePlan` 的 action 在 `await upsertDayPlan` 返回后直接调用 `data.setPlan`。
  切日期期间旧请求落回时，必须防止旧计划和旧保存状态显示到新日期。
- 正常休息日可能有拖地 / 洗衣；**人工切为休息日**带 `mode_override: true`，
  不自动加入家务。动画只改变显示，不得借机改变这条业务规则。
- 页面外壳固定，内容在 `.page-scroll` 内滚；展开的卡片层是全屏固定层
  （当前 `z-index: 40`），确认框 `z-index: 50`，编辑面板 `z-index: 60`。
  全屏演出若放进 `.page-scroll`，会被裁切。
- `/motion-lab` 已是独立实验入口，正式数据不经它读写。
- **`docs/31` 是更新的产品决定：当前正式页小火已移除。**
  本需求不恢复小火、不新造宠物动画。旧的 `docs/30` 中小火条目不适用于本轮。

## 3. 范围与硬边界

### 做

- 为工作日到休息日的**成功保存**增加一次性全屏演出。
- 实验页可模拟确认、保存中、成功、失败、跳过和减少动态效果，不触碰正式数据。
- 正式页沿用现有二次确认、`upsertDayPlan`、保存失败提示 / 重试和休息日业务逻辑。
- 增加必要的、局部的自动回归断言；做桌面和手机截图核对。

### 不做

- 不改变日期模式、DayPlan、三餐、补剂、家务、健身和事项的存储语义。
- 不新增数据库字段、迁移、备份字段、同步接口或新的服务 API。
- 不改 IndexedDB 唯一写入落点，不从页面直连 `localDb` / IndexedDB / Supabase。
- 不改底部导航、周视图、选项页、PWA 外壳或部署配置。
- 不做声音自动播放、震动必选、奖励、排名、streak、反向切换的惩罚动画。
- 不把「切换成功」写成「已同步」，不因动画播放而误报本地保存结果。
- 不在普通事项完成、准备勾选、复制昨天、恢复默认时播放这次庆祝。

## 4. 触发契约

只有**同一次用户确认的模式切换写入**满足以下全部条件，才启动演出：

1. 确认时该日期模式是 `work`，目标模式是 `rest`，且日期可编辑。
2. 用户按了确认，而非取消、关闭、返回。
3. 对该日期执行的 `upsertDayPlan(..., { mode: 'rest', mode_override: true })`
   **确实完成本地写入**；成功必须属于这次操作，不借用其他保存的全局状态。
4. 写入完成时页面仍停留在同一日期的日页；若已经换日期、切视图或卸载，
   写入结果按原业务处理，但**不在另一页播放庆祝**。
5. 一次成功写入只播一次，不能因 React StrictMode、重渲染或计时器重跑播两次；
   刷新页面、重新打开已是休息日的日期都不补播。

| 路径 | 保存 / 页面结果 | 庆祝 |
| --- | --- | --- |
| 今日工作日 -> 休息日，首次保存成功 | 显示休息日真实内容 | 播一次，文案「今天不用上班啦」 |
| 未来工作日 -> 休息日，保存成功 | 显示选中日期的休息日内容 | 播一次，文案「这一天不用上班啦」 |
| 保存失败 -> 原操作重试成功 | 成功后才切模式 | **重试成功时播一次**，失败时不播 |
| 保存失败且未重试 / 重试仍失败 | 模式保持原状，给原有错误提示 | 不播 |
| 休息日 -> 工作日 | 正常保存 | 不播 |
| 取消确认 / 恢复默认 / 复制昨天 | 遵循原有行为 | 不播 |
| 历史日期 | 只读，不能发起切换 | 不播 |
| 写入中切换到别的日期 / 页 | 不在错误的日期展示成功 | 不播，且旧请求不可污染新日期 UI |

文案描述**选中日期**，不能把明天或其他未来日期叫「今天」。既有确认框文案仍先陈述将发生的事实，
「不用上班啦」只在成功后出现。

## 5. 视觉与时间轴

时间从**本地写入成功**算起，保存耗时不计入动画。推荐总长约 `2.2–2.5s`；
节奏在实验页通过真机 / 截图调节，不需逐毫秒照抄。

| 相对时间 | 画面 / 动作 | 语义 |
| --- | --- | --- |
| 确认后到写入完成 | 确认框按既有方式关闭；原页面仍显示工作日，保存栏明确写「正在保存到本地」；避免重复触发 | 结果尚未确定 |
| `0–180ms` | 轻微压暗原页面；从模式卡位置浮出一张**仅用于演出**的「工作日」视觉影像 | 交代旧状态 |
| `180–600ms` | 工作日影像向后轻退；叠放卡片以 2–3 层视觉薄片松开，上浮、错位后淡出 | 紧绷的安排松开 |
| `350–1250ms` | 全屏左右各一次彩带爆发，纸片从两侧向上扬起，再自然下落；中心显示一句大字 | 高潮：突然不用上班 |
| `950–1900ms` | 「休息日」卡片落到原模式卡附近，背景已有**真实**休息日 UI；彩带逐步减少 | 新状态落地 |
| `1900–2500ms` | 影像淡出、清理粒子，露出可操作页面；焦点回到模式区或合理的后续控件 | 恢复正常操作 |

关键表现要求：

- 这不是一个从天而降的通用 confetti toast。**旧卡退场 -> 卡片松绑 -> 彩带爆发 -> 新卡落定**
  应当是一件完整的事。视觉卡片是暂态影像，不能伪造或修改真实计划节点。
- 全屏覆盖整个视口，不局限在居中 760px 内容区；中心文案和卡片仍与内容区对齐。
- 彩带推荐现有玫红、浅珊瑚、薄荷绿、浅金、少量白色等几种色相；
  不用一屏同色、连续闪白、五彩霓虹或不透明遮挡。
- 手机竖屏优先；窄屏长词不断裂、主标题不压跳过按钮，刘海和 Home 指示条留安全区。
- 桌面居中舞台可更宽，但不是整个桌面弹出一张大营销卡。
- 音效默认**没有**。不新增设置项。触感反馈不作为成功判断，也不依赖它完成交互。
- 不改变现有休息日堆叠卡片设计；这是一段过场，而非休息日页面重做。

## 6. 操作、无障碍与降级

- 从演出第一帧起提供可见的「跳过」按钮；点击、Enter / Space、Esc 都可结束演出，
  但**不能撤销已经保存的切换**。动画自然结束也自动关闭。
- 演出期间若拦截页面交互，应使用有标题的可访问模态层，进入时聚焦「跳过」，
  不让 Tab 跑到背景按钮，结束时将焦点交还给休息日模式卡上的合理位置。
  不要复用保存确认框来假装庆祝，也不要增加 `role="application"`。
- 底层彩带 canvas 不进入无障碍树、不接收指针事件；一句文字通过 `role="status"` /
  `aria-live="polite"` 宣告即可，避免逐帧重复朗读。
- `prefers-reduced-motion: reduce` 时**不发射粒子、不滑动 / 缩放卡片**。
  立即显示真实休息日状态，给一次简短的静态成功文案或状态宣告；
  不让用户为一个没有动画的遮罩等待 2.5 秒。
- canvas 不支持、动画资源加载失败、低端设备掉帧时，退化为静态文案和真实休息日页面；
  **演出失败不回滚、更不能覆盖或误报保存结果**。
- 清理所有 `requestAnimationFrame`、定时器与粒子实例；跳过、切页、卸载和 StrictMode
  重挂载时均不可残留画布或再弹一次。

## 7. 实现顺序

### 阶段一：只做动画实验页

1. 在现有 `/motion-lab` 下增加**独立庆祝场景**，建议入口
   `/motion-lab?scene=holiday`；原堆叠卡片实验不丢、不改正式数据。
   尽量仅在 `MotionLabScreen` 内分流，避免为实验页修改 PWA 路由或外壳。
2. 用假的工作日模式卡、假的叠放卡和模拟保存时延呈现完整流程。
   明确标注实验数据；不用业务 API、IndexedDB 或同步代码。
3. 放几个仅实验页可见的控制：今日 / 未来文案、模拟保存成功 / 失败、重播、
   跳过、模拟减少动态效果。保存失败时旧卡不消失、没有庆祝。
4. 演出核心尽量是**可复用的纯视觉组件**：标题、锚点、退出回调由外部传入，
   组件本身不知道 `DayPlan`、日期模式保存或云端状态。建议放在
   `src/shared/components/`，对应样式局部隔离；实验与正式页面使用同一视觉实现，
   不能调好一个演示动画，接入时另写一套效果。
5. 可选用 `canvas-confetti` 提供彩带粒子，使用它的自定义 canvas 和
   `disableForReducedMotion` / `reset` 能力；类型声明按实际版本核对。
   **不要靠 CDN 或外网运行时脚本**。本 PWA 的 service worker 只预缓存 HTML
   直接引用的入口资源：若把动画库单独动态导入，必须验证离线时该 chunk
   可用或提供静态降级；更保守的是随主入口静态打包。不要为此改 service worker。
6. 给阶段演示提供稳定的状态标识（如 `data-phase`），供自动化等候；
   不要以固定 `sleep(2500)` 作为唯一的测试同步手段。

**第一道关口**：手机与桌面分别录短视频或提供关键帧截图：
保存中、退场、彩带高潮、休息日落定、减少动态效果。
用户确认节奏与视觉后，才进入正式页接线。此关口不声称产品功能已落地。

### 阶段二：接入正式页

1. 保留 `ModeCard` -> `ConfirmDialog` -> `upsertDayPlan` 的现有业务链路。
   `DayPlanScreen` 增加**仅用于当次演出**的 UI 状态：目标日期、切换前后模式、
   本次操作 ID / 是否已播、页面上下文、当前演出阶段。不要落库。
   确认当下冻结日期、起始模式和目标模式；不要在异步 action 中重新读取可能变化的
   `selectedDate`。模式卡在本次保存中不允许重复确认，成功回调以操作 ID 去重。
2. 「确认切换」仍调用现有 `runSave`。只在**本次 action 里实际
   `await upsertDayPlan` 成功后**发出演出信号，且同一个 action 的失败重试
   成功也能发出该信号。`runSave` 会吞异常，不能写成
   `await savePlan(...); showCelebration()`；不能用全局 `status === 'saved'`
   的 effect 猜测刚才保存了哪一项。
3. 推荐在原 action 成功回调处做一次性检查：写入对应的日期仍是当前日期、
   仍在日页、目标为休息日、当前有效的操作 ID 未失效；
   然后更新 `data.setPlan` 并启动演出。**失败时不要在 action 内消费“已播”标志**，
   这样原动作重试仍可在成功时庆祝。若决定扩展共享 `useSaveRunner`
   的 per-action `onSuccess`，必须让重试保留**同一个**成功回调，
   不改变其它调用方的保存 / 错误语义。两条实现路径选其一，保持最小改动。
4. 保存中保留真实状态，不允许再次发起同日期模式切换。
   保存失败继续沿用 `SaveStatusBar` 的错误和「重试」，不显示休息日成功文案。
   新的 UI 状态不能阻止原有错误重试。
5. 对切日期、切到周 / 选项、退出登录、组件卸载做失效处理：
   旧请求可以完成其原本写入，但绝不能在新日期弹出庆祝或把旧计划投影到新日期。
   日期 / 视图的有效性标识应在导航事件发生时立即失效，而不是等后续 effect 执行；
   重试保留原日期且只在页面仍对应该日期时开放。当前保存器的日期重置并不会
   阻止旧请求稍后设置 `saved` / `error`，必要时为该链路增加操作代次保护，
   同时拦住 action 内过期的 `data.setPlan`。若触及现有跨日期异步状态问题，
   只修该切换链路并补回归，避免顺手重写全部保存器。
6. 演出层挂在可覆盖视口的位置（如 portal 至 `document.body`），不要置于
   `.page-scroll` 内。明确与卡片展开层、确认框、底部编辑面板的层级关系；
   保存确认框关闭后才出现演出，不应同时叠两层模态。
7. 动画结束 / 跳过后仍是既有的真实休息日页面：
   人工覆盖标识、临时休息日说明、补剂 / 健身 / 自定义事项及家务规则不变。

**第二道关口**：正式路径只播放本地成功动画；验证完整后交付，不以实验页截图代替产品验收。

## 8. 验证计划

### 8.1 自动回归（优先扩展现有 `verify:local`）

至少覆盖：

1. 在**明确设为工作日**的可编辑日期确认切休息日，出现一次演出；
   断言本地计划已是 `rest` 且 `mode_override === true`，动画结束后内容正确。
2. 测试不要假定运行当天为工作日；用日期引擎选择或先把目标日期改为工作日。
3. 取消确认不写入、不演出；休息日切工作日、恢复默认不演出。
4. 人工切休息日后不自动增补拖地 / 洗衣；补剂、健身、自定义事项保留。
5. 用已有 CDP / IndexedDB 故障注入方式模拟这**一次**写入失败：
   原模式不变、无演出、保存栏报错；原动作重试成功后只演出一次。
6. 连点确认只能对应一次写入 / 一次庆祝；刷新已成功的休息日不重播。
7. 保存期间切到另一日期或视图时，不能在新页面显示旧日期的演出 / 成功文案。
8. 今日和未来日期的演出文案正确；历史日期没有切换入口。
9. CDP 模拟 `prefers-reduced-motion: reduce`：数据照常保存，没有粒子运动，
   静态成功信息可被读到，无遮罩长期阻塞。
10. 「跳过」按钮与 Esc 可用，结束后焦点可见且页面可交互；
    原来卡片的点击 / 右滑 / 键盘完成路径不被演出层改变。
11. 本机可断网切换本地模式；不能因为动画依赖未缓存 chunk 而破坏保存或卡在遮罩。

记录可稳定定位的状态和请求结果。为动画阶段等待事件或属性变更，
别仅靠 `sleep` 和截图目测。新增断言要做一次反证，确认故意移除触发条件会报红。

### 8.2 视觉和真机

- 视口至少：`320x568`、`390x844`、`917x1278`、`1440x900`。
- 抓取退场、爆发、落定、减少动态四个关键帧；
  检查中心文字、跳过按钮、彩带可见性、模式卡锚点位置和动画后无残余 canvas。
- 手机触屏与桌面键盘都走一遍；全屏卡片展开状态、底部安全区、竖横屏旋转也检查。
- Chrome 自动化以外，iOS Safari / 安装后的 PWA 动效、帧率和安全区
  **需真机复核**，没有设备就列为未验证，不说“真机通过”。
- 无控制台新增 error / warning，长时间开页面不留无界增长的定时器 / 粒子对象。
