# 幸福小Molly：页面布局自适应优化方案

> 状态：已实施（基础壳层、滚动体系、主日程宽屏双栏与弹层自适应已落地）
>
> 本方案针对两个问题：横屏 / 竖屏、平板分屏与桌面小窗口适配不灵活；页面出现上下或左右滚动条，影响产品质感。

## 1. 优化目标

1. 页面能根据当前可用空间在竖屏、横屏、平板分屏和桌面小窗口之间平稳切换。
2. 横向滚动始终禁止，避免页面出现左右侧边条或内容被横向拖动。
3. 纵向内容仍可访问，但滚动条默认不可见，不牺牲触摸、鼠标滚轮和键盘滚动能力。
4. 每个普通页面只有一个主滚动容器；每个弹层只有一个内部滚动容器。
5. 底部导航、侧边导航、浮动宠物、反馈提示和安全区之间不互相遮挡。
6. 不改变本地优先数据规则、同步语义和现有业务流程。

## 2. 现状与主要问题

### 2.1 应用外壳

`src/app/styles.css` 中 `.page` 当前是最大宽度 `760px` 的固定单列外壳，适合竖屏，但横屏时两侧空间没有被利用。

底部导航 `.bottom-nav` 始终固定在视口底部，主页面需要额外预留约 `60–76px` 的底部空间。横屏手机或矮窗口中，顶部、内容和底部导航会共同争夺有限高度。

### 2.2 核心日程区

`src/features/day-plan/components/todayStage.css` 中 `.bubble-canvas` 使用 `aspect-ratio: 1`，气泡轨道距离主要依赖 `vw`。在横屏矮窗口中，宽度足够但高度不足，正方形画布会制造不必要的纵向溢出。

`src/features/day-plan/components/todayStack.css` 中展开态同时存在 `100dvh`、固定 `354px`、`820px`、移动端 `940px` 等高度。它们在少数设备尺寸上成立，但对横屏、分屏和桌面小窗口不够稳定。

### 2.3 滚动层级

当前主页面、展开态日程、编辑抽屉、动效实验页等多个区域都可能拥有自己的滚动能力。若父子滚动容器同时响应，用户会感觉页面在不同层级之间“抢滚动”。

此外，`overflow-y: auto` 在 Windows 和桌面 PWA 中可能显示系统滚动条；部分固定定位和宽度计算也可能造成真实的横向溢出。

### 2.4 PWA 方向

`public/manifest.webmanifest` 当前使用：

```json
"orientation": "portrait"
```

如果产品需要允许安装后的 PWA 自由横竖屏切换，应在横屏布局完成后改为 `any` 或移除该字段。

## 3. 总体架构

页面采用“自适应应用壳 + 单一滚动体系”：

```text
应用视口
└── AppShell：不滚动，负责方向、安全区、导航模式
    ├── 导航区
    ├── 页面头部
    ├── 主内容滚动区
    └── 弹层 / 浮动反馈层
```

基本原则：

- 应用外壳本身不滚动。
- 普通页面只有一个主纵向滚动容器。
- 弹层只有一个内部纵向滚动容器。
- 所有主要容器 `min-width: 0`，避免 Grid / Flex 子项把父级撑宽。
- 横向滚动始终关闭。
- 滚动条隐藏，但滚动能力保留。
- 弹层打开时锁定背景，滚动只发生在弹层内部。

## 4. 响应模式

不要只按“手机 / 桌面”或 `orientation` 判断布局，而是按当前可用空间划分三个模式。媒体查询用于环境特征，容器查询用于组件排版。

### 4.1 Compact：窄或矮

典型场景：

- 手机竖屏；
- 手机横屏；
- 桌面小窗口；
- 平板分屏。

布局策略：

- 日程主体保持单列；
- 继续使用底部导航；
- 顶部标题、状态条和间距收紧；
- 气泡画布改为受高度约束的矩形，不强制正方形；
- 操作按钮允许换行；
- 内容超出时由主滚动区承载。

手机横屏虽然宽，但高度很小，也应优先归入 Compact，而不是直接套用桌面横屏布局。矮屏可用媒体查询作为兜底：

```css
@media (max-height: 560px) {
  /* 矮屏策略：收紧头部、导航和核心视觉区 */
}
```

### 4.2 Medium：普通竖屏和中等窗口

典型场景：

- 手机竖屏；
- 平板竖屏；
- 中等桌面窗口。

布局策略：

- 保持当前单列日程结构；
- 日期、状态、日程内容纵向排列；
- 保留底部导航；
- 通过 CSS 变量统一间距和尺寸；
- 限制文本最大行宽，避免内容过宽导致阅读效率下降。

这是当前界面的稳定基线，第一轮改造应优先保证该模式行为不回归。

### 4.3 Expanded：宽且高充足

典型场景：

- 平板横屏；
- 宽大的桌面 PWA 窗口；
- 外接显示器或浏览器宽窗口。

布局建议：

```text
┌──────────┬──────────────────────────┐
│ 侧边导航 │ 页面标题                  │
│          ├──────────────────────────┤
│ 执行今天 │ 核心日程 / 气泡区          │
│ 准备明天 │                            │
│ 选项     ├──────────────┬───────────┤
│          │ 今日重点      │ 快捷操作  │
└──────────┴──────────────┴───────────┘
```

布局策略：

- 底部导航切换为左侧垂直导航；
- 主内容使用左右双栏；
- 左侧承载主要日程流程和核心视觉区；
- 右侧承载当天重点、状态和快捷操作；
- 不为了填满屏幕而额外创建多个滚动条；
- 右侧内容随主内容区自然延伸，必要时仍由同一个主滚动区滚动。

建议先使用明确的壳宽度阈值，例如 `900px` 左右，再结合容器查询调整组件内部布局。

## 5. 导航策略

### 5.1 Compact / Medium

保留底部导航：

```text
[ 执行今天 ] [ 准备明天 ]
```

要求：

- 导航宽度跟随应用壳，不使用可能造成溢出的 `100vw`；
- 导航自身不产生滚动；
- 使用统一的 `safe-area-inset-bottom`；
- 主内容只预留导航所需高度，不再散落多个底部补偿值；
- 横屏矮屏时降低导航高度，给内容让出空间。

### 5.2 Expanded

改为左侧垂直导航：

```text
执行今天
准备明天
选项
```

这样可以释放横屏底部高度，并为后续入口扩展保留空间。第一阶段不建议同时保留“横屏底部导航”和“横屏侧边导航”两套竞争性方案。

## 6. 容器查询策略

可复用组件根据父级容器尺寸决定布局，而不是直接依赖全局 viewport：

```css
.bubble-stage,
.page-content,
.option-section {
  container-type: inline-size;
}

@container (min-width: 640px) {
  /* 组件在较宽容器中的内部重排 */
}

@container (orientation: landscape) {
  /* 组件容器横向时的内部布局 */
}
```

适合优先使用容器查询的区域：

- `TodayBubbleStage`；
- 日期头部与状态区；
- 日程重点 / 快捷操作区；
- Preferences 选项列表；
- 编辑表单中的字段组；
- 动效实验页的工作区和检查面板。

媒体查询继续用于：

- `prefers-reduced-motion`；
- `prefers-color-scheme`；
- 触控 / 指针特征；
- 矮屏兜底；
- 浏览器兼容性。

## 7. 核心日程区改造

### 7.1 气泡画布

当前 `.bubble-canvas` 的正方形约束需要改为宽高均可响应：

```css
.bubble-canvas {
  width: 100%;
  height: clamp(250px, 48cqb, 520px);
  max-height: calc(100dvh - 180px);
}
```

实际实现时需要结合组件内容校准上下限，并确保旧浏览器仍有可接受的默认高度。

气泡尺寸和轨道距离应同时参考容器宽度和高度，避免只使用 `vw` 导致横屏矮窗口中的气泡超出画布。

### 7.2 三种内部状态

`TodayBubbleStage` 可分为：

- **Portrait canvas**：竖向容器中围绕中心呈圆形分布；
- **Landscape compact canvas**：横向但矮，压缩纵向半径；
- **Landscape expanded canvas**：宽屏时将气泡区放入左栏，右侧呈现重点信息。

这些状态优先由 `.bubble-stage` 的容器尺寸决定：

```css
.bubble-stage {
  container-type: size;
}
```

### 7.3 展开态

展开态使用动态可视高度和自然内容高度：

- 外层使用 `100dvh` 或等价动态视口策略；
- 卡片列表使用自然内容高度；
- 内容超过可视区域时仅由展开态主滚动容器滚动；
- 去除面向特定设备的 `820px`、`940px` 总高度假设；
- 操作区保持可见，不能被导航或软键盘遮住。

## 8. 滚动条与溢出治理

### 8.1 全局禁止横向滚动

应用基础层应增加明确的横向溢出防线：

```css
html,
body,
#root {
  width: 100%;
  max-width: 100%;
  overflow-x: hidden;
}

.page,
.page-scroll,
.today-stage,
.bubble-stage,
.today-stack,
.motion-lab {
  min-width: 0;
  max-width: 100%;
}
```

实施时还要排查以下潜在来源：

- `100vw` 与滚动条宽度叠加；
- 固定宽度加 padding；
- `position: fixed` 元素超出安全区；
- transform 位移后的浮动宠物和消息气泡；
- 阴影或装饰是否误造成布局宽度；
- Grid / Flex 子项缺少 `min-width: 0`。

### 8.2 隐藏滚动条但保留滚动能力

建议统一抽象滚动区域样式：

```css
.scroll-region {
  overflow-x: hidden;
  overflow-y: auto;
  overscroll-behavior: contain;
  -webkit-overflow-scrolling: touch;
  scrollbar-width: none;
  -ms-overflow-style: none;
}

.scroll-region::-webkit-scrollbar {
  display: none;
}
```

该策略保留：

- 触摸滑动；
- 鼠标滚轮；
- 触摸板滚动；
- PageUp / PageDown 等键盘滚动。

同时不会在 Windows 或桌面 PWA 中显示粗大的系统滚动条。

### 8.3 滚动容器收敛表

| 场景 | 唯一纵向滚动容器 |
| --- | --- |
| 普通日程页 | `.page-scroll` |
| 选项页 | `.page-scroll` |
| 全屏展开日程 | `.today-stack.is-expanded` |
| 编辑抽屉 | `.editor-body` |
| 居中编辑弹层 | `.editor-body` |
| 动效实验页 | `.motion-lab` 或其内部工作区 |

父子容器不应同时使用 `overflow-y: auto`。弹层打开时，背景页面保持锁定，滚动只发生在弹层内容区。

## 9. 视口和安全区

项目已经使用 `viewport-fit=cover`、`visualViewport` 和 safe-area，后续应统一变量口径：

```css
:root {
  --safe-top: env(safe-area-inset-top, 0px);
  --safe-right: env(safe-area-inset-right, 0px);
  --safe-bottom: env(safe-area-inset-bottom, 0px);
  --safe-left: env(safe-area-inset-left, 0px);
}
```

建议：

- 普通页面使用动态可视高度策略；
- 全屏展开区优先使用 `100dvh`；
- 需要防止地址栏变化造成跳动的场景使用 `100svh`；
- 键盘场景继续使用现有 `visualViewport.ts` 写入的变量；
- 底部导航、浮动宠物、反馈提示和编辑抽屉统一使用安全区变量；
- 减少各文件中重复的 `calc(... + env(safe-area-inset-bottom))`。

## 10. Manifest 方向

当前 manifest 锁定为：

```json
"orientation": "portrait"
```

如果确认安装后的 PWA 需要允许横竖屏切换，应在横屏布局完成后改为：

```json
"orientation": "any"
```

或删除该字段，让系统根据设备和窗口决定。不要在横屏布局尚未完成时单独解除方向限制。

- `390 × 844`：手机竖屏；

每个尺寸都检查：

5. 气泡、浮动宠物、反馈提示是否出界。
6. 编辑抽屉的保存 / 取消操作是否始终可达。
7. 内容是否能够完整滚到底。
8. 横竖屏切换后是否出现空白区、布局跳动或内容丢失。

## 14. 最终设计原则

> 容器查询负责组件布局，媒体查询负责环境特征，应用壳负责导航和滚动边界。

最终产品形态：

- 竖屏：单列 + 底部导航；
- 横屏矮窗口：紧凑单列 + 隐藏滚动条；
- 横屏宽窗口：侧边导航 + 左右双栏；
- 所有模式：禁止横向滚动，纵向保留必要滚动但隐藏滚动条；
- 弹层内部独立滚动，背景锁定；
- PWA 允许横竖屏切换；
- 本地优先、云端可选和同步诚实性规则保持不变。
