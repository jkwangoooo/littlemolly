# 幸福小Molly：本地优先执行任务线

## 1. 当前开发决策

当前目标是先把单浏览器内的业务闭环跑通。浏览器 IndexedDB 是当前唯一业务数据源；Supabase、RLS、跨设备同步、真实上线迁移暂不作为本轮开发和验收条件。

这不是放弃云端，而是把云端工作后置。页面和业务模块仍通过 `services/` 访问数据，未来只替换服务实现，不让页面直接依赖 IndexedDB 或 Supabase。

## 2. 已实现基线

- 本地注册、登录、退出和刷新恢复。
- Asia/Shanghai 业务日期、今天/明天/未来/历史判断。
- 固定周一至周日周视图，点击日期进入完整单日页。
- 工作日、休息日和临时模式切换，历史日期只读。
- “执行今天 / 准备明天”切换。
- 工作日五项准备勾选及 `n/5` 进度反馈。
- 三餐、晨间事项、健身决定、自定义事项的底部编辑面板。
- 执行完成勾选、复制昨天、删除确认和保存失败重试。
- `day_plans`、`daily_meals`、`custom_tasks` 的本地存储及当前账号过滤。

## 3. 与需求的差距

| 需求 | 当前状态 | 后续处理 |
| --- | --- | --- |
| 三餐常用食物多选 | 目前是文本输入 | 建立食物选项管理和每日选择快照 |
| 早中晚补剂 | 只有准备勾选，没有实例 | 建立补剂模板和每日补剂实例 |
| 健身项目/动作多选 | 目前是单段文本 | 建立健身选项和每日选择快照 |
| 周末拖地、洗衣 | 未实现 | 创建休息日默认实例，可单独完成 |
| 临时不上班自由规划 | 模式基础已存在，内容规则不完整 | 完善显示范围和自定义事项行为 |
| 底部“今日/本周/选项”导航 | 尚未有选项入口 | 在交互完善阶段补齐 |
| 选项新增、编辑、排序、停用 | 未实现 | 独立选项管理模块 |
| 本地数据升级、备份恢复 | 未实现 | IndexedDB 版本迁移、导入导出和异常恢复 |

## 4. 执行原则

1. 每阶段只处理本阶段范围，完成后再进入下一阶段。
2. 业务数据按用户隔离；任何查询、写入、复制和删除都必须带当前用户边界。
3. 计划内容和执行状态分开保存；复制计划不得复制完成状态或准备勾选。
4. 选项被停用或重命名后，历史计划仍保留当时的名称快照。
5. 页面不直接访问 IndexedDB；所有读写通过服务层。
6. 本地保存成功只能显示“本地已保存”，不得伪装成云端同步成功。
7. 每阶段必须通过类型检查、lint、build，并完成手机和桌面真实操作验证。

## 5. 分阶段任务线

### L0：本地基线整理与契约固定

**目标**：清理本地模式中的遗留命名和边界，作为后续功能的稳定起点。

**任务**

- 将 `normalizeSupabaseError` 等本地服务中的遗留命名改为通用错误命名。
- 固定本地服务接口：日期计划、三餐、自定义事项、选项、每日实例分别定义类型和服务入口。
- 补齐当前已有功能的空状态、加载状态、保存失败重试和只读状态。
- 为准备进度、默认模式、复制规则补充单元测试或可重复的验收步骤。

**验收**：现有功能行为不回退；`npm run typecheck`、`npm run lint`、`npm run build` 通过；桌面和 390px 手机无溢出。

### L1：选项管理与本地数据结构

**目标**：先建立可复用的常用食物、补剂和健身选项。

**任务**

- 新增 `food_options`、`supplement_templates`、`exercise_options` 本地对象仓库。
- 每类选项支持新增、重命名、排序、启用/停用。
- 补剂模板必须包含名称和早/中/晚时段。
- 选项页支持空状态、编辑、删除或停用确认。
- 默认提供少量可编辑的示例选项，但不能写死在页面逻辑中。

**验收**：新增和修改立即在选择器中生效；停用项不出现在新计划选择器中；刷新后数据保留；不同本地账号互不可见。

### L2：计划内容实例化

**目标**：把三餐、补剂和健身从文本字段升级为选项组合，同时保留历史快照。

**任务**

- 三餐按早餐、午餐、晚餐分别多选食物，并支持备注。
- 保存计划时写入食物名称快照；后续重命名不改历史计划。
- 根据补剂模板为目标日期生成早、中、晚每日补剂实例，可逐项勾选执行。
- 健身支持“健身/不健身”；健身时多选项目或动作并填写备注。
- 复制昨天时复制计划内容和名称快照，不复制准备勾选、补剂完成状态、餐食完成状态和健身完成状态。

**验收**：准备页显示选项组合；执行页显示独立完成勾选；刷新恢复完整内容；复制和历史快照规则正确。

### L3：休息日与自由规划

**目标**：完成周末和临时不上班场景，不改变工作日规则。

**任务**

- 正常周六、周日自动出现“拖地”“洗衣”两个每日实例，仅需完成勾选。
- 工作日切换为休息日时，不自动加入拖地、洗衣。
- 休息日保留补剂、健身和自定义事项；隐藏不适用的工作日准备项。
- 休息日切换为工作日时，恢复完整工作日规划入口，并保留二次确认。
- 明确模式切换后已有内容的保留规则，并在界面给出一致提示。

**验收**：周末默认内容正确；临时不上班不带入家务；两种切换文案和可见内容正确；历史日期仍只读。

### L4：首页导航与移动端交互完善

**目标**：让高频使用路径适合手机单手操作。

**任务**

- 补齐底部固定导航：今日、本周、选项。
- 统一所有编辑入口为底部面板；保存/取消后回到原页面和滚动位置。
- 将三餐、补剂、健身选择统一为带勾选的选项行，视觉上与“衣服准备好”一致。
- 优化长列表、面板键盘顶起、确认框、错误提示和空状态。
- 保留桌面宽屏布局，不引入营销式首页或额外提醒功能。

**验收**：手机 390x844 完成注册、登录、准备明天、执行今天、选项编辑、复制和返回；无横向溢出、无遮挡、无控制台错误。

### L5：本地可靠性、备份与回归

**目标**：让本地版本可以稳定使用，并为未来迁移保留清晰边界。

**任务**

- 将 IndexedDB 升级为显式版本迁移机制，新增对象仓库必须可从旧版本升级。
- 增加 schema 校验、事务封装、重复写入和异常恢复处理。
- 提供本地数据导出/导入；导入前确认，格式错误时不得覆盖现有数据。
- 增加核心规则测试：日期、历史只读、模式切换、准备进度、实例化、复制和账号隔离。
- 完成桌面/手机、多日期、刷新、清空缓存后的行为回归，并更新 `README.md` 和 `HANDOFF.md`。

**验收**：从当前版本升级不丢数据；导出后可恢复；关键失败有可见提示；核心回归清单全部通过。

### L6：上线迁移准备（后置，不进入当前开发）

**目标**：在本地业务稳定后，再整体迁移到云端。

**任务**

- 为本地服务实现等价的 Supabase 适配器，不改页面业务接口。
- 将本地对象仓库映射到云端表、RLS 和历史日期约束。
- 编写本地数据到云端的迁移和冲突处理方案。
- 最后再做登录、跨设备同步、断网失败、RLS 双账号和真实上线验收。

**进入条件**：L0-L5 全部完成，且本地数据模型和页面行为不再频繁变化。

## 6. 模块边界

```text
src/features/day-plan/       单日执行、准备、模式和自定义事项
src/features/week/           周视图和日期进入
src/features/preferences/    食物、补剂、健身选项管理
src/services/                本地服务接口和未来云端适配器
src/shared/types/            跨模块类型
src/shared/date/             业务日期和周计算
```

`day-plan` 不直接修改 `preferences` 内部状态；两者只通过共享类型和服务接口通信。每日计划保存选项快照，避免选项管理影响历史数据。

## 7. 当前下一步

下一步执行 **L0：本地基线整理与契约固定**，完成后进入 **L1：选项管理与本地数据结构**。L1 是当前第一个实质业务开发阶段；在 L1 完成前，不继续扩展三餐、补剂或健身页面的复杂交互。
